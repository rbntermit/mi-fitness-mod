# band-5: штатный русский 3.60.0i, журналы Band 10 и Watch 5

## Проверенные исходные данные

- Новый `com.xiaomi.wearable_3.60.0i.apks`: 34 APK, русский сплит, arm64-v8a + armeabi-v7a, все представленные плотности.
- Все 34 APK проходят apksigner verify и имеют одинаковые сертификаты Xiaomi: b031fe98… для API 24–32 и 3fb18466… для API 33+.
- Собираем без RU_FROM. Перевод из 3.59.2i больше не используется; точечные правила патча 20 остаются.
- Приложенные журналы — данные для диагностики. Они не публикуются и не включаются в repo.

## Band 10 (o66gl, 3.2.8, OnePlus, Android 17)

В главном процессе: штатный переключатель синхронизации отвечает успехом, затем простая синхронизация пишет SKIP_UNCHANGED.
При смене режима телефона процесс устройства получает событие и пишет, что simple sync выключена.
Причина в коде: Settings держит SharedPreferences в статическом поле, каждый процесс кеширует своё значение.
Лог не подтверждает успешное применение manual_zen_rule самим браслетом.

Исправление: отдельный однобайтовый файл выбора с блокировкой FileLock, каждый процесс читает свежие данные.
При изменении simple_zen_sync файл обновляется из аргумента переключателя и запускается новая проверка телефона.
Существующий наблюдатель ZenUtils за DND также запускает простую синхронизацию напрямую, независимо от штатного флага браслета. Дисковая работа и отправка выполняются на последовательном рабочем потоке. Старое сохранённое значение мигрирует при первом чтении.
Повтор после смены устройства/отключения не подавляется состоянием другого браслета; отправка только подключённому BLE-устройству.
В журнале написано queued: вызов отправителя сам по себе не доказывает применение режима браслетом.
Переключатель остаётся по умолчанию выключенным. На Band 10 нужно проверить включение и выключение DND с новым журналом.

## Watch 5: исправление прежней классификации

В журнале модель **o61w**, не o61/o61lte. Прямые свидетельства: DualCoreWearOSDeviceModel, isWearOS=true,
isDualCoreWearOS=true. Нельзя переносить вывод по китайской модели o61 на эту модель.
Типы Product.type 6/7 сами по себе не доказывают DualCoreWearOS: у Band 10 o66gl в каталоге тоже pd_type=7.

Google WatchApi существует, но getWatchByPeerId возвращает null. FaceWearOsHelperImpl возвращает sync error 2
`getWearOSWatch == null`; список циферблатов также отсутствует. Значит, симптомы связаны с отсутствующим объектом
часов в Google Wear SDK, а не с русскими ресурсами. Из этого журнала неизвестно, почему Google SDK не выдаёт часы.
HTTP 429 относится к планам тренировок; наличие OkCallback в стеке не доказывает ошибку переписывания ответа.

Изменения совместимости:
- патч 01 пропускает enqueue и ответы без модификации для Product.type=1 (включая DualCoreWearOS), а также
  до определения модели. device.local и FaceFix в этих случаях не вмешиваются;
- патч 03 сохраняет исходный/явно заданный Core service для Wear OS и неизвестной модели. Lyra разрешена только
  известному BLE-продукту, если служба существует, включена, экспортирована и доступна по разрешениям;
- при выборе Core service нельзя рекурсивно обращаться к инициализирующемуся DeviceManager;
- новые строки MOD wear показывают состояние списка спаренных часов (pending, error, count) без peer id и MAC.

Это устранение вмешательств мода и уточнение диагностики. Восстановление Wear OS-соединения **не подтверждено**.
Нужен журнал band-5 со старта приложения до открытия циферблатов. Если список Google SDK остаётся пустым/ошибочным,
следующий шаг зависит от фактической ошибки SDK. Привязку, Google Play services и проверки подписей вслепую не меняем.

## Проверки

Тесты покрывают исключение Wear OS, сохранение BLE типов 6/7, выбор существующей службы и общий флаг DND
при чтении из разных экземпляров с устаревшими preferences. Реальные сценарии Watch 5/Band 10 ждут устройств.
Установка новой сборки — только после подтверждения; прошивки и другие файлы на браслет не отправляются.
Генератор hooks исправлен: diff вызывается без shell, поэтому символ $ в именах вложенных классов сохраняется; ошибки diff завершают сборку. Регрессионная проверка — scripts/test_hooks.sh.

Итог сборки: 307 тестов успешно. Подпись и выравнивание проверены; 131 строк разрешений совпадают со стоком. SHA-256 APK: 852878e57bcf0deb48ac816700c54e8725997760d10f50e9ebf680a58f9b4c47. На телефон не установлено.
