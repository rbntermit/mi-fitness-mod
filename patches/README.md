# Патчи band-mod для Mi Fitness

Применяются `build.sh` по порядку имён папок. Пути в `smali.patch` заданы по имени класса
(`a/com/x/Y.smali`), `build.sh` сам находит нужный `smali_classesN`.

| Папка | Что внутри |
|---|---|
| 00-core | новые классы `com.markus.*` (в отдельный dex), меню устройства, `Settings.init`, строки en/ru, activity выбора файла |
| 01-watchface-install | `RealCall.enqueue`: локальные превью (`device.local`) и подмена ответов магазина для локальных циферблатов. С band-3 (`com.markus.facefix.FaceFix`, хук в конце `OkCallback.onResponse`): список «Установлено» (`/ops/v1/paidwatchface/v4/list`) получает имя и превью циферблатов, поставленных из файла; если сервер отвечает на детали такого циферблата пустым телом, ответ собирается из файлов мода (`result.watchface`), поэтому экран деталей открывается без ошибки |
| 02-rpk-third-party-apps | `DeviceModelExtKt.isSupportFeature`: `third_party_no_market` для всех, кроме Wear OS |
| 03-hyperos3-signature | `CoreExtKt.targetPackageName` → `com.xiaomi.lyra`; `XiaomiAccountManager` → системного аккаунта нет |
| 04-notifications-dedup | `BaseNotifySyncService`: последнее из пачки + `NotificationDeduplicator` |
| 05-dnd-sync | `ZenUtils.isSupportZenMode` → true; односторонняя синхронизация `manual_zen_rule` |
| 06-china-region | пропуск окна «материковый Китай» во всех 4 местах и диалога смены региона |
| 07-hide-health-summary | `HealthV2Fragment.requestHealthSummary` (хук в `hooks.txt`) |
| 08-manual-weather-location | `WeatherLocationService$onStartCommand$1.locationSuccess` |
| 09-app-language | `DeviceSettingsSyncer`: своя локаль для браслета |
| 10-android-compat | `List.getFirst()` (Android 15+) → `Compat.first()` |
| 11-no-secret-logs | `Rc4Codec.decode` больше не пишет `ssecurity` в logcat; кодек работает как раньше |
| 13-disable-firebase-stats | `OnetrackImpl`: убраны 2 вызова `FirebaseAnalytics.report` (как в alpha-4) |
| 12-firmware-install | Устройство → Ещё → «Прошивки»: список прошивок во внутреннем хранилище, диагностика, проверки, ручная установка полного пакета; по отдельному переключателю (по умолчанию выключен) — переход Smart Band 11 cn/tc с 4.100.x на полный q66gl 4.200.x с двойным подтверждением (`FwPolicy.isCrossgrade`). Java-код в `src/`, заглушки классов приложения в `stubs/`, тесты в `test/`. Отправка включена (`FwGate.INSTALL_ENABLED = true`); перед отправкой экран берёт у патча 16 разрешение на этот файл. Отключается целиком: `FIRMWARE_INSTALL=0 ./build.sh` |
| 14-fix-copyfile | `copyFile` пишет только прочитанные байты (`IoCompat.copy`); заголовки циферблата читаются до конца (`IoCompat.readUpTo`) |
| 16-guard-stock-ota | штатное обновление прошивки работает как в оригинале, кроме двух случаев: перепрошитый браслет (регион модели cn/tc не совпадает с веткой прошивки, которую сообщает браслет) и предложение другой ветки (4.100 ↔ 4.200), не новее текущей или с непонятной версией. Тогда — блокировка предложений, экранов, тихого обновления и передачи на браслет с тостом. Решение принимает одна функция `com.markus.ota.StockOtaPolicy.decide`; что нельзя определить надёжно — блокируется. Передача (`prepareOta`, `startOta`, `sendFile` типа 2) — только для разрешённого штатного обновления или по разрешению экрана «Прошивки» на конкретный файл |
| 17-skip-guide-webpage | последний шаг руководства после привязки (веб-страница): кнопка «Пропустить», автозавершение при ошибке загрузки, сертификата или без страницы за 10 с; руководство не открывается повторно (`com.markus.guide.GuideSkip`) |
| 18-github-update-check | проверка новых сборок мода на GitHub (`releases/latest` репозитория rbntermit/mi-fitness-mod, без токенов и данных об устройстве): раз в сутки и вручную в Устройство → Ещё → «Обновление мода»; переключатель «Проверять обновления»; «Скачать» открывает страницу релиза в браузере (`com.markus.update`) |
| 19-phone-steps-off | переключатель «Не учитывать шаги телефона» в настройках мода (по умолчанию выключен): шагомер телефона (MIUI) сообщает «не поддерживается», шаги только с браслета (`com.markus.steps`) |
| 20-declutter | скрыты: бейдж сладостей в «Здоровье», «спящее животное» и баннер «Улучшите качество сна», «Соревнование» и «Отчёт» в «Профиле», рекламные баннеры (в «Профиле», на «Тренировке» и на «Устройстве»), «Интерактивные сенсорные курсы»; иконки быстрого старта по центру; исправления перевода. Каждый пункт — отдельный блок в `rules.txt` и `hooks.txt` (`com.markus.declutter`) |
| 21-log-export | журналы, которые можно достать: «Сбор журналов» после запроса открывает экран, который ждёт файлы журнала браслета и упаковывает их в ZIP; новый пункт Устройство → Ещё → «Журнал приложения» — logcat процессов самого приложения за последние 15 минут (без READ_LOGS и root), с маскировкой токенов, ssecurity, passToken, serviceToken, MAC, did, серийных номеров, e-mail и телефонов (`com.markus.logexport.LogMasker`). Оба сохраняются через «Сохранить как…» (ACTION_CREATE_DOCUMENT) или «Поделиться» (FileProvider приложения, папка `Download/`), без новых разрешений; перед отправкой — предупреждение о личных данных |

Патчи с `src/` компилируются `build.sh` (`javac` → `d8` → smali) и проверяются тестами из `test/` до сборки APK.
`./build.sh --tests-only` — только компиляция и тесты.

`hooks.txt` — хуки методов. `build.sh` применяет их во время сборки скриптом `scripts/make_hooks.pl` к текущей версии
приложения (после предыдущих патчей): код вставляется перед первой инструкцией метода или рядом со строкой-якорем,
со своими метками `:markus_*`, поэтому номера меток и имена вокруг не важны; скрипт проверяет номера регистров.
Обфусцированные имена (`edj`, `b46`, `h0v`...) свои у каждой версии приложения — при переносе их надо найти заново.

`rules.txt` — точные правки ресурсов и встроенных бандлов React Native (`scripts/text_rules.pl`): у каждого правила
своё ожидаемое число совпадений, иначе сборка останавливается. Изменённые бандлы `build.sh` переупаковывает,
пересчитывает их MD5 в `bundleInfo.json` и помечает как «только встроенные» (хук в 20-declutter).
